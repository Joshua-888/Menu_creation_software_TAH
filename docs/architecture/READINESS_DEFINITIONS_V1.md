# Readiness Definitions V1

Three separate readiness concepts — do not collapse.

## A. INTELLIGENCE_READY

Source can become an approved TargetMenu:

- extraction + evidence ledger complete enough
- `runMenuIntelligence` produces TargetMenu
- MenuQualityContract accounting acceptable for operator preview
- no silent sparse coverage (fail closed)

## B. EXECUTION_READY

Approved TargetMenu can be safely written and verified:

- explicit operator approval with hash binding
- destination capabilities CERTIFIED for planned ops
- immutable WritePlan / RecoveryPlan
- field-aware + menu-level verification path available
- category exposure strategy understood (`CATEGORY_CREATE_IS_PUBLIC_MUTATION`)

## C. LIVE_READY

Verified menu can be safely published and storefront-verified:

- `VERIFIED_COMPLETE_HIDDEN`
- PublicationPlan visibility-only
- per-product publish + content unchanged
- storefront 12/12 (or N/N) visible
- → `VERIFIED_LIVE`

## Completeness

A merchant is **fully complete** only at:

```text
VERIFIED_LIVE
```
